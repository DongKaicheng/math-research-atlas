## What can I send?

Please use the category that best fits your message:

- **Question** — ask about a definition, statement, argument, or project.
- **Correction** — explain an error, missing assumption, or unclear proof step.
- **Reference** — suggest a relevant paper, book, note, or existing theorem.
- **Idea** — propose an improvement or new research direction.
- **Proof** — submit a complete or partial mathematical argument.
- **Counterexample** — present an example that challenges a statement.
- **Lean / formalization** — share a Lean proof or a formal statement.

## How to submit feedback

1. Visit the [feedback page](/feedback/) and choose your category.
2. Sign in with a **GitHub account** when GitHub asks you to.
3. Enter a clear title and explain your question or contribution.
4. Give the project link, permanent theorem ID, and version number when relevant.
5. Submit the GitHub Issue. The public discussion starts immediately.

You can come back to the same Issue at any time and reply beneath the original message. GitHub can notify you when someone comments or when the issue changes.

## How to upload a LaTeX or Lean ZIP

GitHub accepts `.zip` files as attachments to Issues and comments. In the issue editor, **drag and drop your ZIP file or use GitHub's attachment control**. Wait for the upload to finish before submitting the Issue.

A useful source package contains:

- A main `.tex` file with the exact statement and argument, or `.lean` source files.
- A short `README.md` explaining how the files fit together.
- Bibliography files, figures, styles, and other inputs needed to read the argument.
- A note identifying the theorem or conjecture, the relevant website version, and references.

Use an ordinary, unencrypted ZIP. Follow GitHub's current attachment size limits. **Neither this website nor its maintainers automatically execute or compile an uploaded archive.**

## Are comments and attachments public?

**Yes. All GitHub Issues, comments, names, and attachments are public as soon as they are submitted.** Only post material you are permitted to share. Do not include confidential notes, passwords, personal documents, or unpublished work you wish to keep private.

If you need private correspondence, contact the maintainer through a separately agreed private channel.

## What happens to a proposed proof or correction?

Comments are welcome from anyone with a GitHub account. An Issue is a place to discuss a claim; it is not a publication of a new theorem. A maintainer checks proposed mathematical changes, their exact assumptions and dependencies, and then opens or reviews a GitHub Pull Request to update the published content.

The repository owner and approved GitHub collaborators control merges to the website. Everyone can read the source and propose changes. Each accepted revision remains traceable in Git history.
